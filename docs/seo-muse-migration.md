# SEO Muse Ember 移行

新規 SEO ジョブのテキスト処理は Meta Model API の `muse-ember-1.0`、推論強度 `medium` を使用する。検索・引用の取得は既存の GPT-6 Luna と回数制限を維持する。旧 v3 Haiku ジョブの履歴・監査は保持し、再開要求を送信・予約前に停止する。v4 のモデル、生成条件、呼び出し監査を別テーブルに固定する。生成上限は 48,000 tokens、長文処理の期限は従来どおりである。

費用予約は、入力 20 万 tokens 超の単価を全入力・出力に適用する上限として計算し、キャッシュ割引を見込まない。実行あたり 1.25 ドル、通常月 7 ドルの上限と、失敗・不明時の予約保持を維持する。価格の出典は [Meta の価格表](https://dev.meta.ai/docs/pricing-rate-limits) と [Muse Ember](https://dev.meta.ai/docs/muse-ember)。

2026-11-11 に隔離 Cloudflare Worker と実際の SEO 生成 builder を使い、合成ファイル、48,000 tokens、`medium`、strict schema の推論を確認した。期待する合成ファイル差分を受信し、入力 543、出力 176 tokens、予約上限 75,364 microUSD、所要 2.469 秒だった。これは実記事・検索・校閲を含む本番受入を証明しない。

配備時は先に D1 migration `0047_seo_muse_models.sql` を適用し、既存行・予約・モデル監査の保持を確認した後に Worker を配備する。既存実行がある場合はモデル固定と期限を確認し、無人実行に先立ち、認可された限定 canary で計画、検索根拠、生成、校閲、監査、予算を照合する。合成試験は本番受入の代わりにはならない。

新規投入で問題が発生した場合は受付を停止し、作成済み v4 ジョブ・監査・予算予約を保持して原因を確認する。旧 Haiku の送信経路は廃止済みであり、`SEO_AI_MODEL` の変更だけでは復旧できない。コードを旧版に戻す前に v4 の実行状態と必要な認証を確認し、途中のジョブや監査を削除しない。v2 専用の一部の特別復旧は v4 に適用できず、安全側に停止する。
