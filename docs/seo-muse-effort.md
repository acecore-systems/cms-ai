# SEO Muse の段階別推論契約

新しい Parallel v5 ジョブに `0049_seo_muse_effort.sql` の不変契約を追加する。候補選定は low、事前計画と取得本文の照合は medium、記事生成と最終レビューは max。旧 v1–v5 の契約・呼出記録は変更せず、旧 v5 は medium のまま。契約により 48,000 token 上限の生成条件も固定する。

予約と実送信、研究証跡の再構成には同じ serialized payload を使用する。入力バイト数の事前確認も対応する effort を用いる。`max_tokens` の出力枠には推論を含む。既存の 1 run $1.25、月 $7 の上限、期限、失敗・結果不明の予約保持は変更しない。max が制限内で完成する保証はなく、制限や検証に抵触すれば従来どおり停止する。

本番導入ではまず D1 へ migration を適用・確認してから Worker を反映する。migration だけでは旧 Worker の新規ジョブは従来の medium 契約のまま。Worker のロールバック時、旧 Worker は新 effort 契約を解釈できないため、新契約ジョブの作成を停止し、進行中ジョブを終了または安全に停止してから旧版へ戻す。既存行や監査記録は削除しない。

合成受入では、候補選定 low・取得本文照合と計画 medium・生成とレビュー max の実送信、同一 payload の予約ハッシュと証跡再検証、上限・期限内停止を確認する。実記事を使わず、公開や Draft PR 作成を行わない合成入力で行う。実 API を使う場合は課金されるため既存の予算枠内で予約する。ローカル fixture と CI の成功は本番受入を意味しない。
